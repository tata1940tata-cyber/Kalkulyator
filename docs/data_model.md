# Модель данных и методика расчёта

Калькулятор юнит-экономики Яндекс Маркета: какие данные нужны, откуда их брать и по каким формулам считать.

Версия: 1.0 (ноябрь 2026). Все ставки в примерах — демонстрационные.

---

## 1. Что нужно калькулятору

Минимальный набор, без которого расчёт невозможен:

1. **Тарифы площадки** — комиссия по категории, логистика по объёму, последняя миля, эквайринг, хранение, возвраты, утилизация, штрафы. Привязаны к дате и схеме работы (FBY / FBS / DBS).
2. **Характеристики SKU** — категория, схема, габариты и объём, себестоимость, упаковка, доставка до склада, доля возвратов.
3. **Цены** — текущая, минимальная, цены в акциях.
4. **Акции** — тип, скидка или фиксированная цена, ДРР на период, взнос за участие.
5. **Настройки расчёта** — налоговый режим, целевая маржинальность, целевой ДРР, правило округления.

Всё остальное — производные величины.

## 2. Состав пакета

| Файл | Назначение |
|---|---|
| `data/settings.json` | Настройки расчёта: налоги, цели, округление, параметры API |
| `data/tariffs.json` | Тарифы площадки по схемам FBY и FBS, версионирование |
| `data/skus.csv` | Товары с характеристиками и текущими ценами |
| `data/promos.csv` | Акции и условия участия |
| `data/expected_results.csv` | Эталонные расчёты (golden cases) для приёмки |
| `tools/reference_calc.py` | Референсная реализация: читает данные и считает |
| `tools/build_export_template.py` | Сборка Excel-шаблона выгрузки |
| `Шаблон_выгрузки_данных.xlsx` | Тот же набор данных в виде таблиц для заполнения вручную |

## 3. Поток данных

```
API Маркета ─┐
Кабинет ─────┼─> нормализация ─> tariffs / skus / promos / settings ─> калькулятор ─> результаты
Выгрузка ────┤                         (валидация + версия тарифов)
Учётная система ─┘
```

Приоритет источников при конфликте: **ручное подтверждение → выгрузка → API**. Причина: тарифы меняются по договору, а API может отдавать не все условия.

### 4.2 Тарифы (`tariffs.json`)

Тарифы версионируются: `version`, `valid_from`, `valid_to`. Для каждой схемы (`FBY`, `FBS`, `DBS`) задаётся одинаковый набор блоков.

| Блок | Содержимое | Как применяется |
|---|---|---|
| `commission_by_category` | `{category_id: rate}` | Ставка комиссии от цены |
| `default_commission` | ставка | Fallback, если категории нет в словаре (с предупреждением) |
| `logistics_tiers` | ступени объёма: `volume_from_l`, `volume_to_l`, `price_rub` | Фикс за единицу по объёму упаковки |
| `last_mile` | `rate`, `min_rub`, `max_rub` | Процент от цены с ограничителями |
| `acquiring` | `rate`, `included_in_commission` | 0, если включён в комиссию Маркета |
| `storage` | `rate_per_liter_day`, `free_days` | ₽ за литр в сутки × объём × дни |
| `returns` | `fee_per_return_rub`, `commission_refunded` | Доля возвратов × стоимость возврата; комиссия возвращается или нет |
| `utilization` | `fee_per_unit_rub` | Плата за утилизированную единицу |
| `fines` | `rate` | Плановая доля штрафов от выручки |
| `delivery_to_warehouse_rub` | число | Используется, если у товара не задано своё значение |

## 5. Формулы

Обозначения: `P` — цена продажи, `k` — ставка комиссии категории.

**Выручка**

```
R = P                         (без НДС в цене)
R = P / (1 + vat_rate)        (если vat_in_price = true)
```

**Статьи расходов на единицу**

```
Комиссия            C  = P × k
Логистика           L  = тариф по объёму (ступень)
Последняя миля      LM = min(max_rub, max(min_rub, P × lm_rate))
Эквайринг           A  = P × acq_rate
Хранение            S  = storage_rate × volume_l × days
Возвраты            Ret = return_rate × (return_fee + (1 − commission_refunded) × C)
Утилизация          U  = utilization_fee × return_rate
Штрафы              F  = P × fines_rate
Доставка до склада  D  = delivery_to_warehouse_rub
Реклама / ДРР       Ads = P × drr_rate
Прочее              O  = P × other_rate
Налоги              T  = R × tax_rate                         (УСН «доходы»)
                    T  = max(0, R − E_без_налога) × tax_rate  (УСН «доходы − расходы»)
Себестоимость       COGS
Упаковка            Pack
```

**Итого и маржа**

```
E = C + L + LM + A + S + Ret + U + F + D + Ads + O + T + COGS + Pack
M = R − E
Маржинальность = M / R
ROI к себестоимости = M / COGS
```

**Цена под целевую маржинальность `m`**

Аналитическое решение (без лимитов последней мили):

```
P* = (COGS + L + S + Ret_фикс + D + Pack) / (1 − var − m)
var = k + lm_rate + acq_rate + fines_rate + drr_rate + tax_rate + other_rate
```

Из-за лимитов последней мили, НДС и налога на прибыль формула кусочно-нелинейная, поэтому в референсной реализации цена находится бисекцией: маржинальность монотонно растёт с ценой. Затем цена округляется вверх и проверяется ограничение `min_price_rub`.

Если текущая маржа уже выше целевой, расчётная цена будет **ниже** текущей — это корректный результат: либо снижаем цену, либо повышаем ДРР. Если такое поведение не нужно, добавьте флаг «не снижать цену» в настройки.

**Цена входа в акцию**

```
P_promo = promo_price_rub                                   (FIXED_PRICE)
P_promo = current_price × (1 − seller_discount_rate)        (DISCOUNT)
M_promo = P_promo − E(P_promo, drr_rate акции)
```

Решение об участии: `M_promo ≥ 0`, `M_promo ≥ targets.min_margin_rub`, `P_promo ≥ min_price_rub`.

## 6. Пример расчёта (OFF-1001, кофеварка)

Текущая цена 4 490 ₽, категория 101 (комиссия 10%), объём 23 л, себестоимость 2 100 ₽.

| Статья | Сумма, ₽ |
|---|---|
| Комиссия 10% | 449,00 |
| Логистика (ступень 15–25 л) | 120,00 |
| Последняя миля 5,5% | 246,95 |
| Хранение 0,15 ₽/л/сутки × 23 л × 45 дней | 155,25 |
| Возвраты 3% × 60 ₽ | 1,80 |
| Утилизация 30 ₽ × 3% | 0,90 |
| Штрафы 0,7% | 31,43 |
| Доставка до склада | 40,00 |
| Реклама / ДРР 10% | 449,00 |
| Налог 6% | 269,40 |
| Прочее 1% | 44,90 |
| Себестоимость | 2 100,00 |
| Упаковка | 60,00 |
| **Итого** | **3 968,63** |
| **Маржа** | **521,37 (11,6%)** |
| ROI к себестоимости | 24,8% |

Цена под целевую маржинальность 20% при ДРР 10%: **5 300 ₽**, маржа 1 062,45 ₽ (20,05%).

В акции «11.11» со скидкой 8% (4 130,80 ₽) и ДРР 14%: маржа 116,19 ₽ (2,8%) — ниже минимального порога 200 ₽, участие не рекомендуется без компенсации.

## 7. Источники данных и обновление

| Данные | API | Кабинет | Выгрузка / учёт |
|---|---|---|---|
| Карточки, габариты, категория | да | да | — |
| Цены, скидки | да | да | — |
| Акции и условия участия | частично | да | — |
| Комиссия, логистика, хранение, возвраты | как правило, нет | **да** | ручная выгрузка тарифов |
| Себестоимость, упаковка | нет | нет | **да** |
| Налоги, НДС | нет | нет | бухгалтерия |

Практическая схема: карточки и цены тянем по API, тарифы и себестоимость — из выгрузки, акции — из кабинета или API, если ваш договор даёт доступ.

Правила синхронизации:

* тарифы кэшируются и пересчитываются при смене версии (`valid_from`);
* если тариф не найден — использовать `default_commission` и помечать результат флагом;
* все ответы API сохранять с `last_sync_at`, чтобы понимать актуальность;
* конкретные методы и поля сверять с актуальной версией Partner API (`api.partner.market.yandex.ru`).

## 8. Валидация

Обязательные проверки перед расчётом:

* `volume_l > 0`, `current_price_rub > 0`, `cogs_rub ≥ 0`;
* `0 ≤ commission_rate < 0.6`;
* `last_mile.min_rub ≤ last_mile.max_rub`;
* `0 ≤ return_rate ≤ 1`;
* `1 − var − target_margin > 0`, иначе цель недостижима — вернуть понятную ошибку;
* после округления пересчитать маржу (округление вверх её не снижает, вниз — может);
* `P ≥ min_price_rub`, иначе поднять цену и показать предупреждение;
* флаги результата: `отрицательная маржа`, `ниже минимальной цены`, `ниже целевой маржинальности`, `маржа ниже минимума`.

## 9. Допущения

* Расчёт на одну единицу и одну отправку, без дробления заказа.
* Скидки и субсидии площадки моделируются только через цену акции; промокоды и баллы — вне модели.
* Хранение — по среднему сроку, без учёта сезонных тарифов и неликвида.
* Налоги упрощены: УСН «доходы» — от выручки, УСН «доходы − расходы» — от прибыли.
* Валюта — рубли, НДС — только через настройки.
* Штрафы и утилизация — плановая доля, а не фактические списания.

## 10. Что подтвердить у бизнеса

1. Схема работы по каждому SKU: FBY, FBS или DBS.
2. Налоговый режим, ставка НДС и момент его начисления.
3. Что считаем маржой: выручка минус все расходы, включая рекламу и налоги? (в модели — да).
4. Целевая маржинальность и целевой ДРР — единые или разные по категориям.
5. Можно ли снижать цену, если текущая маржа выше целевой.
6. Правило округления цены: до 10 ₽, до 50 ₽ или «психологические» 99.
7. Источник минимальной цены: MAP, договор с поставщиком или решение категорийного менеджера.
8. Кто отвечает за актуализацию тарифов и с какой частотой они меняются.
